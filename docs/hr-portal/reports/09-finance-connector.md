## 2. Design as built

**Pull (Finance → FlowZa Time).** `pullAttendance` POSTs `{ device_serial, token, since?, limit }` (limit default 500, max 1000) to `<baseUrl>/attendance-export`. Each punch becomes a `RawTransaction`: `providerTransactionId` = Finance `id`, `deviceEmployeeId` = `employee_number ?? pin` (rows with neither are skipped and counted), `punchedAt` = `time_utc` (UTC; sub-millisecond digits truncated deterministically), `deviceLocalTime` in the producing device's zone, `verificationMethod`/`direction` from `verify`/`state`, `rawPayload` = allowlist `{ financeId, employeeNumber, pin, source, deviceSerial, deviceTimezone, state, verify, workcode, lat, lng, accuracy, geofenceVerdict, geoFlagged, createdAt, connectorSerial }` (bounded strings). The stored cursor is `{ since: next_cursor }` verbatim; on an empty page (`next_cursor` null) the position we asked from is kept — including a synthesised rewind position, never "from the beginning". `hasMore` = Finance's `has_more` **and** a non-empty page **and** an advancing cursor; the engine's page cap (20 pages/run, then the next poll in 1 minute) bounds the loop.

**Push (FlowZa Time → Finance).** Per run: load the connector, stop when direction is `pull`, check the circuit, read the keyset position, then batches of ≤ 500 `attendance_events` in creation order `(created_at, id) > position`, filtered to: this organisation, not voided, `source ∈ {DEVICE, MOBILE, IMPORT, CORRECTION}`, not produced by the connector (neither `device_id` nor the raw transaction's `device_id`), older than a 5-second settle window. Each event maps to `{ pin: <employee's pinKey field>, time: punched_at ISO UTC, verify: method (unknown ⇒ null), state: PUNCH_IN→check_in, PUNCH_OUT→check_out, BREAK_START→break_out, BREAK_END→break_in, PUNCH→null, workcode: null, lat/lng/accuracy from the raw payload }`; employees without that field are skipped and counted. `provider.pushAttendance` POSTs `{ device_serial, token, punches }`; **only after a 2xx** does a separate transaction advance `last_pushed_event_id/at`. At most 20 batches per run; when more remain, `next_push_at = now` so the next tick continues. Health (device online, heartbeat) and the circuit are updated only when a request actually went out.

**State.** `finance_sync_state` holds the push position and both directions' last run, counts and the failure streak; pull cursors stay in `sync_cursors` like every device's. The API's status endpoint joins both plus the provider circuit, the connector's unmatched/pending raw counts and its last five pull/push jobs.

**Failures.** Provider errors map to the sync engine's codes (401/403 `AUTH_FAILED`, 400 `PROTOCOL_ERROR`, 404/405 `INVALID_CONFIG`, 429 `RATE_LIMITED` with Retry-After, 5xx/network `VENDOR_ERROR` retryable, abort `TIMEOUT`, 3xx `PROTOCOL_ERROR` — redirects are never followed). `runItem` applies the standard retry backoff; vendor-level codes feed the per-account circuit breaker; auth/config errors flag the device `error`. Every failed attempt of either direction increments `consecutive_failures`; the third emits `sync.finance.failed`.

**Egress.** The base URL must be `https` on a public host (IPv4 private/loopback/link-local/CGNAT/multicast, IPv6 loopback/ULA/link-local/mapped, `localhost`, `*.local`, `*.internal`, `*.lan` and bare names refused), no credentials, query or fragment. Enforced on save and test by the API (`resolveFinanceBaseUrl` + the existing `assertEndpointAllowed` egress helper) and on every call by the provider. `FLOWZA_ALLOW_PRIVATE_EGRESS=true` (local development against the mock server only) relaxes it.

## 5. Loop guards

1. **Finance never exports what the connector pushed** (Finance side: `attendance-export` excludes rows whose `device_id` is the connector's own device).
2. **FlowZa Time never pushes what it pulled.** Pulled punches are raw transactions of the connector device, and their events carry `device_id` = connector; the push excludes events whose `device_id` **or** whose raw transaction's `device_id` is the connector. Tested: the pulled events exist in `attendance_events` and none of their times reaches the mock Finance.
3. The connector is excluded from employee pushes (capabilities false), reconciliation (scheduled and manual) and plan seats; its row can only be changed through the integration endpoints.

## 7. Decisions (recorded)

1. **Permission grants follow Prompt 1's matrix** (owner + org_admin). The first draft also granted `attendance_admin`; dropped after the rebase — widening a Prompt 1 grant is not this prompt's call.
2. **State keyed by connector device**, not `(org, direction)` as sketched in the prompt pack: one connector per org in practice, both directions on one row, and the device FK gives cascade + RLS for free. Pull cursors stay in `sync_cursors`.
3. **Push position = `(created_at, id)` keyset**, stored as Postgres **text** (microseconds intact — a JS `Date` truncates to ms and would re-select the last row forever), plus a 5-second settle window against late commits. `attendance_events.id` is random and `punched_at` can be back-dated, so neither orders creation.
4. **No `state='void'` markers for voided events** (prompt pack suggested them, "Finance ignores"). Verified in the Finance repo: `ingest_punch` stores `punch_state` verbatim and no pairing/recompute code filters on it, so a marker would be counted as a real punch at the voided time. Voided events are simply not pushed; removals are a known limit.
5. **Identity order for pulled rows:** configured PIN field → explicit reconciliation mappings → otherwise unmatched; the generic `device_user_id` fallback is skipped for connector rows (a Finance number or foreign terminal PIN coinciding with a local device user id would silently mis-attribute). Employee numbers compare via `lower(employee_number::text)`: the worker's `search_path` lacks `extensions`, so a bare comparison on the citext column silently turns case-sensitive (caught by a test).
6. **`deviceStatus: true`** in addition to `attendancePull`, so the ordinary health check probes the connector (limit-1 export) — the only honest liveness signal for a push-only connector with nothing to send.
7. **`PUSH_ATTENDANCE`** as the job type (new enum value) and **`finance-push`** as the scheduler tick name (house style for tick names; the brief's "`finance.push` task" is this tick + job).
8. **Three-segment event type** `sync.finance.failed` (the brief's name) — required relaxing the `domain_events` CHECK, done additively (`not valid` + `validate`).
9. **Adaptive polling disabled for the connector**, so the configured interval is the real cadence (Finance shows the device Stale/Offline from the time of last contact).
10. **Health/circuit only on real contact:** a push run with nothing to send records its (empty) run in the state but does not mark the device online.
11. **Generic device mutations refuse the connector** (and the wizard hides the provider behind a default-off flag); the connector takes no plan seat and is not reconciled.
12. **Mock Finance server shipped from the package** (`createMockFinanceServer`) so provider, worker and API tests exercise the real HTTP path, and **`allowPrivateHosts`** is an explicit option / env flag rather than a test-only code path.

## 9. Known limits and open items

- **Removals are not propagated** (Decision 4). Needs a Finance-side void/delete endpoint keyed on the pushed punch.
- **Late attribution in Finance does not re-attribute an already-pulled row** (raw rows are immutable and dedupe on Finance's id); map the Finance PIN in FlowZa Time's reconciliation instead. Finance's recommended daily re-pull is not scheduled — a manual **full re-sync** (Sync → attendance) re-reads safely; the commit-order window it would close is milliseconds wide.
- **Egress check is name/pattern based** (like the existing helper): a public hostname resolving to a private address is not detected; no DNS pinning.
- `consecutive_failures` counts every failed attempt of either direction (retries included), so a flapping pull can raise the alert while pushes succeed; the alert fires once per streak.
- Adaptive polling is org-wide; the exemption is keyed on the provider.
- Playwright e2e mock backend (`apps/web/e2e/support/mock-backend.ts`) not extended with the integration endpoints; notification templates (en/ar) for `sync.finance.failed` belong to Prompt 8; live round trip against the Finance project is Prompt 12.
- The device list still shows the connector (for health, logs and raw-punch filtering); its edit/credential/remove actions answer 409 with a pointer to Settings → Integrations rather than being hidden.

### 10.1 Security

**D1 (P0) — SSRF / port-scan oracle → one shared egress guard.** New `packages/device-providers/src/egress.ts`, the single guard for outbound calls to tenant-configured hosts, used by the API on save and on test (`validateFinanceBaseUrl` → the provider's `vetBaseUrl`), by the generic device helper (`assertEndpointAllowed` → `hostnameBlockReason`) and by every Finance call (`egressRequest`):
- *Syntax:* https only; no userinfo; one trailing dot stripped before anything is judged; IP literals classified in every spelling (IPv4 decimal / hex / octal / short forms as the WHATWG parser and `inet_aton` read them; IPv6 including v4-mapped, v4-compatible, NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, Teredo): loopback, RFC 1918, link-local, CGNAT, unique-local `fc00::/7` (Fly's `fdaa::`), site-local `fec0::/10`, multicast, unspecified, reserved/benchmark/documentation and anything outside `2000::/3` are refused; names `localhost`, `*.localhost`, `*.local`, `*.internal`, `*.lan`, `*.localdomain`, `*.home.arpa`, `*.intranet`, `*.corp`, `*.home`, `*.private` and single-label names are refused.
- *DNS:* the host is resolved (`dns.promises.lookup(host, { all: true })`, 5 s budget) and refused if ANY address is not public — `localtest.me`, `*.nip.io` and friends are caught before a socket opens.
- *Pinning:* the request connects to the address that was checked (custom `lookup`, `agent: false`), while the Host header, TLS SNI and certificate verification keep the hostname — DNS rebinding between check and connect cannot reach a private address.
- *Transport:* redirects are never followed; failures are reported with a GENERIC reason (`refused_by_policy` / `unreachable` / `tls_error` / `timeout` / `too_large`) — never a socket code (`ECONNREFUSED`, `ERR_SSL_…`) or a response body, so the test endpoint no longer tells an open port from a closed one. Finance's error bodies are logged, never returned.
- `FLOWZA_ALLOW_PRIVATE_EGRESS=true` (local development / the mock server) is the only bypass. A refused URL is a 400 `VALIDATION_ERROR` "Finance base URL must point at a public host".

### 10.2 Push correctness

**D3 — per-punch errors advanced the position.** A 2xx whose `errors + skipped > 0`, or whose `ingested + duplicates` falls short of what was sent, is **not delivered**: nothing of the batch is recorded, the position does not move, the failure counts in the streak, and the batch is retried with a short back-off (1, 2, 4, 8 minutes, capped at the poll interval; Finance dedupes what it did store). After `FINANCE_PUSH_BATCH_MAX_ATTEMPTS = 5` attempts of the same batch it is skipped as **poison**: its events go to the ledger as `poison_skipped` (never sent again), the run fails, and `sync.finance.failed` is emitted for it whatever the streak (`reason: "batch_skipped"`, with the number of punches and the first event id). The attempt counter lives in `finance_sync_state.push_retry_event_id / push_retry_attempts`; the status card shows "attempt n of 5". *Tests:* worker "W1: an answer with errors > 0 does not deliver the batch; it is retried (Finance dedupes) and delivered when Finance stores it", "a batch Finance keeps rejecting is retried 5 times, then skipped as poison with an alert, and never sent again".

**D4 / D11 — late commits skipped; concurrent runs doubled traffic.** The `(created_at, id)` keyset is gone. New table **`finance_pushed_events`** `(organization_id, device_id, event_id, pushed_at, outcome ∈ pushed|no_pin|poison_skipped, primary key (device_id, event_id))` — RLS exactly like `finance_sync_state` (read with `device.view`, written only by the system context of the same organisation, client INSERT/UPDATE/DELETE revoked so a client write raises). Each run scans the window **[position − 15 min, database now − 5 s]** (both ends from the DATABASE clock), pushes the events of that window that are **not in the ledger**, and records them there; a transaction that commits up to 15 minutes after its `created_at` is therefore still pushed, and nothing is sent twice by FlowZa Time. When the window is drained the position (`finance_sync_state.push_position_at`, monotonic via `greatest()`) moves to the window's end; a run cut by the batch cap stops at the last handled event. Ledger rows are pruned after 48 hours, never while inside a run's window. One run per connector at a time: a session-level `pg_try_advisory_lock(hashtextextended('finance-push:<device>', 0))` on a dedicated connection, held for the whole run; a second run exits as a no-op (`skipped: "already_running"`), and a crashed worker's connection releases it. *Tests:* worker "W2: an event whose transaction commits after a run moved past its created_at is still pushed", "W9: two concurrent runs send every punch once (the second run is a no-op)"; RLS suites (14 new assertions on the ledger: own-org read for owner and branch manager, cross-tenant 0, employee 0, client insert/update/delete raise; system context records and prunes its own organisation only, cross-org insert raises).

**D8 — corrections of pulled punches were pushed back.** A CORRECTION event is not pushed when its correction chain (an edit of an edit…, followed back up to 10 levels through `attendance_corrections.original_event_id`) leads to an event produced by the connector — directly or through its raw transaction. `SET_STATUS` corrections are never pushed (they are verdicts, not punches); an `ADD_PUNCH` correction (a punch HR added) is pushed. *Test:* worker "W10: an EDIT of a pulled punch (and an edit of that edit) is never pushed back; an ADD_PUNCH correction is".

**D5 — the streak reset on runs that never contacted Finance.** Only a real Finance success closes a streak: a successful pull, or a push run that made at least one request and delivered everything (no retry, no poison). A push with nothing to send touches neither `consecutive_failures` nor `last_error`. The alert fires when the streak reaches 3 — once per streak, again only after a real success reset it. *Test:* worker "W5: pull failures between push runs that had nothing to send reach the threshold and alert once; only a Finance success resets".

**D16 — the alert went to people who cannot open the page.** `sync.finance.failed` is routed to **`integration.manage`** holders (owner and org_admin by default), who can act on `/settings/integrations` (the link is kept); `device.sync`-only roles no longer receive a dead link. Chosen over re-linking to `/sync` because the fix (token, base URL, serial, PIN field) is only possible in Settings → Integrations. *Test:* worker "sync.finance.failed notifies integration.manage holders (who can act on /settings/integrations), not device.sync-only roles".

### 10.3 Pull correctness

**D6 — a push-only connector was pulled.** Push-only is enforced at every door: `devices.capabilities.attendancePull = false` and auto-sync off (API on save; the migration backfills existing rows); the scheduler never plans a pull for it; the pull handler skips it without calling Finance (`skipped: "direction_push"`), whatever queued the item; `POST /sync/attendance` excludes it (with `all: true`, and an explicit `deviceIds` naming only it answers 400); the device action `sync-attendance` answers 422 `DEVICE_UNSUPPORTED_OPERATION`; sync-now queues only the push. Switching back to both restores the capability and auto-sync. A pull-only connector still never pushes (existing test kept). *Tests:* worker "W6: the pull handler skips it without calling Finance, and the scheduler never plans a pull for it"; API "D6: a push-only connector is not pull-capable: sync-all skips it, its sync-attendance action is refused, sync-now queues only the push".

**D7 — pulled rows matched on the configured PIN field.** Pulled punches are resolved ONLY by Finance's employee number against our `employees.employee_number` — trimmed, case-insensitive, same organisation, not deleted, not terminated/resigned (`handlers/attendance/finance-identity.ts`). `pinKey` now only chooses what the PUSH sends. A Finance punch Finance itself could not attribute arrives under a namespaced identity `pin:<finance device serial>:<pin>` and stays **unmatched** (visible, triageable) — a raw terminal PIN never matches a device user id or card number, whatever `pinKey` says. A Finance row without an employee number is therefore never attributed by FlowZa Time. *Tests:* worker "W7: resolved only by Finance employee number; a raw terminal PIN never matches a device user id or card, whatever pinKey says"; provider "D7: keeps an unattributed Finance PIN under a namespaced identity (never a bare PIN)…"; `finance.test.ts` identity expectations updated.

**D10 — transient HTTP failures reset a valid cursor.** Only an unreadable STORED cursor is a cursor problem (`INVALID_CONFIG` with `details.reason = "invalid_cursor"`, raised by `parseFinanceCursor`; `isFinanceCursorError`). Every HTTP-level failure — 400, 404, 405, 3xx, 5xx, a malformed body — is a retryable `VENDOR_ERROR` (401/403 stay `AUTH_FAILED`, 429 `RATE_LIMITED`): the run fails, counts and retries with back-off, and the cursor is kept, so no unpulled row older than a rewind is skipped. *Tests:* worker "W8: a gateway 404 / 400 / 503 / malformed answer keeps the cursor; the next run resumes and misses nothing"; provider "D10: a 400 / 404 / 405 / redirect / malformed answer is a RETRYABLE vendor failure and never a cursor error…".

**D12 — every tenant shared one throttle / circuit account.** The connector's account key is `sha256("flowza_finance|<organization>|<connector device>")[0:16]` (worker throttling, circuit breaker, the API's test path and the status card's circuit row all use it). A throttle wait that this worker gives up on (`details.reason = "throttle_wait_aborted"`) is local queueing, not Finance failing: it feeds neither the streak nor the circuit and does not mark the connector offline. *Tests:* worker "two tenants' connectors on the same Finance URL never share an account key", "W14: a throttle wait this worker gives up on is its own queueing, not Finance failing — no streak, no circuit failure, device not marked offline"; provider "builds a per-tenant, per-connector account key…".

### 10.4 Configuration lifecycle

**D9 — re-pointing kept the old cursor and position.** When the base URL or the serial changes (PUT), in one transaction: the pull cursor is emptied (the old one kept in `previous_cursor`, `rewind_reason = "connector_repointed"`), the push position, retry marker and ledger are cleared, the failure streak and last error are reset, **`devices.generation` is bumped**, the old serial joins `config.previousSerials` (the pull drops Finance rows whose `device_serial` is ours, current or previous — Finance only loop-guards the current device), and `integration.finance_repointed` is audited (serials, base URLs, `tokenReplaced`, `tokenDeleted`, generation; never the token). The stored token belongs to the old identity: a new one is required to keep the connector enabled, and a disabled connector re-pointed without one has its stored token **deleted**. A worker run in flight when the generation changes writes nothing afterwards (no cursor, no raw rows, no position, no ledger — it ends `superseded`). *Tests:* API "D9: re-pointing (serial or base URL) resets the pull cursor, the push position and ledger, bumps the generation, replaces the token and is audited"; worker "writes neither the position nor the ledger once the connector generation changed under it"; provider "D9 loop guard: never imports punches this connector pushed under an earlier serial".

**Observation — Disconnect.** New `DELETE /api/v1/orgs/:orgId/integrations/finance` (`integration.manage`): disables the connector (no auto-sync, no scheduled push), deletes its token, clears the cursor (`rewind_reason = "connector_disconnected"`), push position, retry marker, failure streak and ledger, bumps the generation, audits `integration.finance_disconnected`, and returns the connector (`enabled: false, hasToken: false`). **Observation — start date (`syncFrom`).** New connector setting (`YYYY-MM-DD`, a calendar day in the connector's timezone; default 30 days before the day it is set up; the migration gives existing connectors 30 days before their creation, so nothing already in scope is dropped). **D15 — blocking index on the partitioned `attendance_events`: decision, not a code change.** The hosted Supabase apply wraps each migration file in a transaction, and so does the local runner (`packages/database/src/tools/migrate.ts`); `create index concurrently` cannot run inside one, and a non-transactional file would break both. `20260928000400` keeps its plain `create index if not exists attendance_events_org_created_idx … (organization_id, created_at, id)` under `lock_timeout = 5s` (a busy table makes the migration fail fast instead of queueing and blocking punch inserts behind it) and `statement_timeout = 120s`. **Measured** on the seeded database (22 955 – 23 290 events over 37 partitions): 65 – 137 ms (cold 137 ms, warm 65 ms; re-measured 78 ms and 101 ms), index 1.6 MB — the SHARE lock is held for that long. The new push query still uses the index (the window is a `created_at` range per organisation). **Runbook for a large hosted table** (Prompt 12, before applying `000400`): create the index out-of-band without blocking — `create index if not exists attendance_events_org_created_idx on only public.attendance_events (organization_id, created_at, id);` then, per partition, `create index concurrently if not exists <partition>_org_created_idx on public.<partition> (organization_id, created_at, id);` and `alter index public.attendance_events_org_created_idx attach partition public.<partition>_org_created_idx;` — the migration's statement is then a no-op.

### 10.6 Still open (recorded)

- **Removals are still not propagated** (Decision 4): a punch voided in FlowZa Time after it was pushed stays in Finance. Needs a Finance-side void endpoint.
- **A transaction longer than the 15-minute overlap** whose events commit after the window moved past them is still missed by the push (a normaliser batch or import that long would be pathological); a full re-push can be forced by moving the start date earlier.
- **Poison batches:** the batch is skipped as a whole (Finance's answer does not say which punch it rejected). The skip is counted in the push item's result and alerted (with the first event id and the number of punches); once Finance accepts them, moving the start date earlier re-sends them (the ledger is emptied).
- **Late attribution in Finance:** a Finance punch pulled before Finance attributed it stays `unmatched` under its `pin:` identity — the raw row is immutable and deduplicated on Finance's id, so a re-read does not replace it, and (per D7) nothing but Finance's employee number attributes a pulled punch. The prevention is to keep Finance's own terminals' PINs mapped in Finance (Workforce Config → PIN Mapping); an affected day is corrected in FlowZa Time like any missing punch.
- `consecutive_failures` is one streak for both directions (by design: one alert per failing connector).
