## 2. Reference — how Finance does it (condensed; the full inventories are in Appendix A/B)

**Roles & scope.** HR is org-wide; a *line manager* is whoever an employee's `manager_id` / `secondary_manager_id` points at and needs **no HR permission** to act on their own reports; a *branch manager* is branch-scoped; the employee sees only their own rows through self-scoped SecDef RPCs (`get_my_attendance`, `submit_attendance_note`, `checkin_punch`). Approve/reject/return are separate permissions from edit.

**Approval engine.** `approval_policies (entity_type, active)` → `approval_policy_levels (level_number, approver_type ∈ specific_user|role|reporting_manager|manager_chain|hr_admin, approval_mode ∈ any|all|quorum, required_count, min_amount)` → `approval_requests` (pending/approved/rejected/cancelled/invalidated) → `approval_request_levels` (per approver: approved/rejected/pending/skipped, delegate). Rules: levels form a prefix; a level is satisfied per its mode; rejection is terminal only when the level can no longer be satisfied; no policy ⇒ auto-approved request row; the **subject** (employee the request is about) can never approve it, even when HR filed it; delegation (`approval_delegations`) routes to the delegate while active and in-window; reminders and escalation run from a cron; the request is invalidated when the underlying document materially changes, and cancelled when the document is withdrawn/voided; every decision is in the History view with who/when/comment.

**Attendance notes (per-day reasons).** Employee explains a day (`client_visit | field_work | late_reason | absence_reason | wfh | other`); one active note per employee per day; statuses `pending → approved | rejected | excused | info_requested` (info requested → employee edits → back to pending); the mapped manager reviews (HR/owners have an explicitly-marked *oversight* view); on **reject** the manager chooses the pay effect — half day / full day / no deduction — which charges paid leave first (annual → casual → most remaining, special types excluded) and otherwise flags **loss of pay**; approve/excuse restore any deduction; a nightly sweep auto-processes unexplained absent/late/incomplete days after a grace period when the org enables it.

**Regularisation.** Requests of type missed punch / wrong punch / WFH unmarked / system downtime with the proposed times → approval → applied to the record; HR bulk-approve.

**Check-in.** Server time only (client time ignored), `evaluate_geofence` verdicts (`no_fences_assigned`, allowed, flagged, logged, denied outside, denied mock), replay/duplicate guard, web + mobile switches in policy, IP allow-list optional, offline queue replayed through the same validation; selfie check-in for employees granted "open attendance", reviewed by HR.

**Portal attendance stats.** Avg hours/day over worked days, attendance % of working days (half day = 0.5, approved leave excluded), late days, leave days, "improvement required" hints (attendance < 90 %, avg day < 8 h, late arrivals, absent days, missing check-outs), punctuality last 7 days / this month / last month.

**HR register.** Table + calendar views; filters employee/department/status/date; add/edit record with auto-calculated hours and policy-derived status (manual override tracked as `status_source`); bulk set status; punch timeline per day; "Sync punches"; export CSV/PDF; monthly summary per employee (present, late, half day, on leave, absent, missed punch, days worked, total/overtime hours, avg/day); comments & approvals report; report share (in-app/email now, monthly schedules on day N for previous month / MTD / custom window).

**Shifts & holidays.** Shift catalogue with grace/early-departure/break/off days, effective-dated assignments, calendar view, swap requests; holiday calendars per branch/country with company days.

**Leave.** Types with paid flag, applicability (gender), carry-forward rules, accrual, opening balances/allocations per employee per year; requests with half day & period, overlap exclusion, advance-notice/max-consecutive validation, edit/withdraw before approval, comment thread (ask info → reply & resubmit), approval through the engine, team upcoming leaves, comp-off credits earned on holiday/weekly-off work and redeemed as leave.

### Prompt 9 — Flowza Finance ↔ FlowZa Time attendance sync connector

**Design (decided):** punch-level, both directions, one credential pair, no schema change in Finance beyond one new read endpoint.

## 5. Decisions log (pack-level)

1. Line manager is a **role + relationship**: the relationship (`manager_employee_id`) grants team visibility and approval rights through RLS/engine; the `manager` role only adds the workspace permissions. A manager who is also HR keeps org scope.
2. Approval configuration stays in `approval_workflows` (per entity type, optional branch scope, thresholds) rather than a new policy table — one engine, Finance semantics.
3. Employee identity across systems for the sync = `employee_number` by default.
4. Pay-effect charging writes an APPROVED internal leave record (auditable, reversible) instead of mutating balances directly; LOP is a flag on the day + a period-summary column, never a payroll write.
5. No new npm dependencies unless unavoidable; maps are optional.
6. Everything is feature-flag free but permission-gated: tenants control exposure through roles and the attendance settings switches (web/mobile check-in default **off**, geofence `flag`, auto-deduct **off**).


## 6. Inventory findings that change the prompts (Prompt 0 output, 2026-09-27)

Full report: `docs/hr-portal/inventory/flowza-time-current-state.md`. Facts every implementing agent must respect:

1. **Every raw punch needs a `device_id`** (`attendance_raw_transactions`), and identity resolution runs `device_employee_states → employee_provider_identities → employees.device_user_id`. Therefore **self-service punches (Prompt 4) and Finance-pulled punches (Prompt 9) are modelled as devices**: one system-owned virtual device per organisation per source, created lazily (`provider_key = 'self_service'`, model "FlowZa Self-Service"; `provider_key = 'flowza_finance'` for the connector), never listed for sync, and resolving the employee directly (self-service: the membership's `employee_id`; connector: `employee_number`). The dedupe hash and the normaliser stay untouched.
2. **The user↔employee link is `org_memberships.employee_id`** (`employees.user_id` exists but is unused) — use `app.own_employee_ids()` / `grant.employeeId` everywhere; never `employees.user_id`. `acceptInvitation` drops the employee link for new accounts (defect) — Prompt 1 fixes it by carrying `employee_id` on `invitations`.
3. **Approval routing today:** ROLE steps match on role **id** (a custom role holding `attendance.approve` cannot act on an `hr_admin` step); `approval.pending` notifies *every* `attendance.approve` holder; nothing is emitted when a request advances; there is no request-detail, history or "my requests" endpoint; the `/approvals` route needs `attendance.approve` and the inbox needs `attendance.view` under RLS, so a plain manager cannot act. Prompt 2 replaces all of that: ROLE steps match by permission **or** role id; notifications go to the resolved actors only; `approval_steps`/`approval_step_actors` get an *assignee* select policy so a manager with only the `manager`/`employee` role can read and decide their own queue; request detail + history + my-requests endpoints exist.
4. **Domain events are a closed list** (`DOMAIN_EVENT_TYPES` + the relay ROUTING table) — every new event type (notes, punches, swaps, comp-off, approvals v2, reports) must be added to both, with targeted recipients (`payload.userIds[]`), and Settings → Notifications org toggles + `notification_preferences` must finally be honoured (Prompt 8). `domain_events` is never pruned — Prompt 8 adds a retention purge (keep 90 days).
5. **Defects to fix in the phase that touches the area:** dashboard/daily view count `status = 'MISSING_PUNCH'` which the engine never emits (use the `MISSING_IN`/`MISSING_OUT` flags — Prompt 3); `settings.attendance.defaultShiftId` is never read by `load-inputs.ts` (Prompt 3); `recalculations-tab.tsx:40` links `/sync/<queue job id>` (Prompt 6); `report.export` and `notification.manage` are declared but never enforced (Prompts 6/8); `employee_self_service` feature flag unused (leave permission-gated, document it).
6. **Leave today** is a PENDING `leave_records` row decided by `PATCH /leave-records/:id` under `leave.manage`; balances are advisory (`annual_allowance_days`); no engine involvement — Prompt 7 routes leave through the engine and keeps the direct HR path only for `requires_approval = false` types.
7. **No public API / API keys / outbound webhooks are implemented** — the Finance connector (Prompt 9) therefore lives entirely in the worker (provider pull + push task) and needs no inbound endpoint on FlowZa Time.
8. **Tests:** API tests run against per-file databases created by `apps/api/src/test/harness.ts`; worker tests use the mock provider; Playwright uses `apps/web/e2e/support/mock-backend.ts` — extend the mock backend for every new endpoint the UI calls.
